## `IconSource`

The interface every icon backend implements — astro-icon's own `iconifyLocalSource`/`iconifyApiSource`/`localSource` included. Imported as a type from `astro-icon/loaders` or `astro-icon/loaders/live`.

```ts
interface IconSource {
  name: string;
  getIcon(name: string): Promise<IconEntry>;
  listIcons?(): Promise<string[]>;
  getVersion?(): Promise<string | undefined>;
}
```

| Member | Required | Description |
| --- | --- | --- |
| `name` | Yes | Identifies this source in error messages and, for a live collection, generated types. For a live collection, set it to the same key you register the loader under in `live.config.ts` — a `LiveLoader` is never told its own collection name by Astro. |
| `getIcon(name)` | Yes | Builds one icon by name. Throw a descriptive error if it can't be found or built. |
| `listIcons()` | Build collections only | Lists every icon name this source can build. Required for `createIconLoader`, which loads exactly this list. Optional for a live collection, where it additionally enables `getLiveCollection()` and full autocomplete instead of a plain `string` type. |
| `getVersion()` | No | A cheap freshness signal (e.g. an installed pack's npm version). If every source in a collection reports one and it matches the last sync, `createIconLoader` skips re-building. Omit if there's no reliable way to tell "nothing changed" short of building. |

See [“Bringing Your Own Source”](/guides/bring-your-own-source/) for a full example.

## `parseIconSVG(svg, options)`

Turns a raw `<svg>...</svg>` string into a render-ready `IconEntry`: runs `optimize` first if given, then parses the result into `{ body, viewBox, width, height }`, deriving a `viewBox` if optimization stripped it.

```ts
function parseIconSVG(svg: string, options: ParseIconSVGOptions): Promise<IconEntry>;

interface ParseIconSVGOptions {
  /** The collection this icon belongs to. Passed through to `optimize` and used in warnings/errors. */
  collection: string;
  /** The icon's name within that collection. Passed through to `optimize` and used in warnings/errors. */
  name: string;
  optimize?: OptimizeFn;
  strict?: boolean;
  logger: Pick<AstroIntegrationLogger, "warn">;
  /** Fallback intrinsic size if optimization strips the viewBox and none can be recovered from the SVG's own attributes. @default { width: 24, height: 24 } */
  fallbackSize?: { width: number; height: number };
}
```

A generic entry point for any `IconSource` that produces a full `<svg>...</svg>` string per icon — reach for it inside your own `getIcon` once you have raw SVG in hand, the way `iconifyLocalSource`/`iconifyApiSource`/`localSource` do internally.

## `IconEntry`

The shape every icon collection stores in Astro's content layer, and what `entry.data` gives you from `getEntry()`/`getLiveEntry()`. You won't normally construct this yourself — `parseIconSVG` builds it for you.

```ts
interface IconEntry {
  /** The inner SVG markup, everything between the outer `<svg>` tags. */
  body: string;
  /** The icon's `viewBox` attribute, taken from the source SVG or derived from its width and height. */
  viewBox: string;
  width: number;
  height: number;
}
```

## `AstroIconError`

The error class every built-in source throws for a recoverable, descriptive failure — a missing icon, an uninstalled pack, an `icons` allowlist miss. Alongside a `message` it carries a `hint` describing the fix, which loaders surface in build warnings and `<LiveIcon>` logs.

```ts
import { AstroIconError } from "astro-icon/loaders";

throw new AstroIconError(
  `Icon "${name}" not found in the design system API.`,
  `Check the name at https://icons.example.com, or that your API token has access.`,
);
```

Re-exported from both `astro-icon/loaders` and `astro-icon/loaders/live`. Throwing it from your own `getIcon` gets your source the same error presentation the built-in ones have — a plain `Error` works too, it just won't carry a hint.
