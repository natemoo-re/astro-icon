A **source** is what actually produces icons. It's astro-icon's own contract, [`IconSource`](/reference/icon-source/) — Astro never sees it directly. Sources are passed to a [loader](/reference/loaders/), which adapts them into something Astro understands.

The relationship is **N sources → 1 loader → 1 collection**: several sources can be composed into a single collection.

All of the following are exported from both `astro-icon/loaders` and `astro-icon/loaders/live`.

## `localSource(dir, options?)`

An `IconSource` backed by a directory of local `.svg` files.

```ts
function localSource(dir: URL | string, options?: LocalSourceOptions): IconSource;
```

This is what [`localIcons()`](/reference/loaders/#localiconsdir-options) uses internally, minus the directory watching. Reach for it directly when you need to compose a local directory with other sources, or when the directory ships inside a library package:

```ts
import { createIconLoader, localSource } from "astro-icon/loaders";

createIconLoader(localSource(new URL("../icons/", import.meta.url)));
```

A `URL` resolves directly, independent of the consuming project's root — which is what makes it correct for [library-shipped icons](/guides/shipping-icons-from-a-library/). A plain `string` path is only resolved against `config.root` by `localIcons()`.

Each file's path relative to `dir`, minus the extension, becomes its icon name: `<dir>/logos/deno.svg` is `"logos/deno"`.

### `LocalSourceOptions`

```ts
interface LocalSourceOptions {
  /** Restricts this source to a fixed list of icon names. Omit to allow every `.svg` file found. */
  icons?: string[];
  /** Transform applied to each icon's raw SVG before it's parsed and stored. */
  optimize?: OptimizeFn;
  /** Turns a missing or unreadable icon file into a build error instead of a warning. @default false */
  strict?: boolean;
  /** Where warnings are reported; defaults to `console.warn`. */
  logger?: Pick<AstroIntegrationLogger, "warn">;
}
```

## `iconifyLocalSource(pack, options?)`

An `IconSource` backed by a locally installed `@iconify-json/<pack>` package **only**. Throws if the pack isn't installed — there is no network fallback by design.

```ts
function iconifyLocalSource(pack: string, options?: IconifySourceOptions): IconSource;
```

```sh
npm install -D @iconify-json/mdi
```

```ts
createIconLoader(iconifyLocalSource("mdi", { icons: ["home", "account"] }));
```

The `icons` option is typed and autocompleted against the pack's own catalog, once astro-icon has recorded it from a previous sync. A duplicate name in that array is deduped and logged as a warning, not rejected at the type level.

## `iconifyApiSource(pack, options?)`

An `IconSource` backed by the public Iconify API **only**. Resolves any icon name in the pack, one at a time, regardless of `icons`.

```ts
function iconifyApiSource(pack: string, options?: IconifySourceOptions): IconSource;
```

Useful for a pack you'd rather not install, and the natural fit for a live collection where names aren't known ahead of time.

:::caution
Without an explicit `icons: [...]` allowlist, `listIcons()` **throws** rather than pretending to enumerate the pack — the API can only resolve icons you name, never "everything in the pack." That makes a bare `iconifyApiSource("mdi")` unusable for a build collection (which loads exactly `listIcons()`), but perfectly valid for a live one.
:::

### `IconifySourceOptions`

Shared by both Iconify sources:

```ts
interface IconifySourceOptions {
  /** Restricts this source to a fixed list of icon names, typed against the pack's catalog once recorded. */
  icons?: string[];
  /** Transform applied to each icon's raw SVG before it's parsed and stored. */
  optimize?: OptimizeFn;
  /** Turns a recoverable warning into a build error instead. @default false */
  strict?: boolean;
}
```

`icons` is an allowlist for pinning a design system's approved icons — and, for `iconifyApiSource`, the thing that makes the source enumerable at all. Omitting it on `iconifyLocalSource` allows the whole installed pack.

## `mergeSources(sources)`

Normalizes one or more `IconSource`s into a single `CompositeSource`, trying each in order per icon (first match wins).

```ts
type CompositeSource = IconSource;
function mergeSources(sources: IconSource | IconSource[]): CompositeSource;
```

The loaders call this for you when you pass an array, so reach for it directly when you want the merged source as a reusable value — for example, a local-preferred/API-fallback Iconify source shared by a build and a live collection:

```ts
const mdi = mergeSources([
  iconifyLocalSource("mdi", { icons: ["home"] }),
  iconifyApiSource("mdi", { icons: ["home"] }),
]);
```

On the result:

- **`getIcon`** tries each member in order; it only fails if every member fails, and the error lists what each one reported.
- **`listIcons`** returns the union of every member's list.
- **`getVersion`** only reports a value if *every* member does — so one member without a version signal disables the whole collection's up-to-date check.

## `OptimizeFn`

The shape of every source's `optimize` option:

```ts
type OptimizeFn = (svg: string, ctx: { collection: string; name: string }) => string | Promise<string>;
```

astro-icon runs no optimization unless you pass one. See [SVGO & optimize()](/guides/optimize/) for the `svgo()` helper built on top of this.
