Astro Icon's main API is an `Icon` component that automatically inlines an `<svg>` directly in your markup, resolved at build time from a collection you define in `src/content.config.ts`.

<Showcase code={`---
import { Icon } from "astro-icon/components";
---

<!-- Embed the contents of the /src/icons/logo.svg file -->

<Icon name="logo" size={32} />`}>
  <Icon name="logo" size={32} />
</Showcase>

Because Astro Icon is powered by Astro, this component only renders on the server to static HTML. It has no runtime footprint.

## Sizing

`size` sets both dimensions at once. Set `width` and `height` individually for a non-square icon, or pass `null` to omit the attribute and size the icon from CSS instead.

<Showcase
  code={`<Icon name="mdi:rocket" size={16} />
<Icon name="mdi:rocket" size={24} />
<Icon name="mdi:rocket" size={32} />
<Icon name="mdi:rocket" size={48} />`}
>
  <Icon name="mdi:rocket" size={16} />
  <Icon name="mdi:rocket" size={24} />
  <Icon name="mdi:rocket" size={32} />
  <Icon name="mdi:rocket" size={48} />
</Showcase>

## Props

```ts
interface Props extends HTMLAttributes<"svg"> {
  name: IconName;
  title?: string | { id?: string; value: string };
  desc?: string | { id?: string; value: string };
  size?: number | string;
  width?: number | string | null;
  height?: number | string | null;
}
```

- **`name`** is `"collection:icon"` for any collection you define, or a bare icon name if you have a collection named `icons`, as in the example above. It autocompletes and type-checks against every collection you've defined, once you've run `astro sync`, `dev`, or `build`.
- **`title`** and **`desc`** add an accessible `<title>`/`<desc>` inside the `<svg>`, and take the icon out of its decorative default (see below). Pass `{ id, value }` instead of a plain string when something _outside_ the icon needs to reference the same id — e.g. a button that wraps an icon and wants to reuse its title as the button's own accessible name.
- **`size`** sets both `width` and `height` at once, and takes priority over either if you set both. Set `width` and `height` individually to render a non-square icon.
- By default, `<Icon>` renders with `width`/`height` set from the icon's intrinsic size. Pass `width={null}`/`height={null}` to omit the attribute entirely, e.g. to size the icon from CSS instead.

`<Icon>` also accepts any global HTML and `aria-*` attribute, and forwards it to the rendered `<svg>`.

## Accessibility: decorative vs. labeled

By default, `<Icon>` renders as decorative: `aria-hidden="true"`, invisible to assistive tech. That's the common case, since most icons sit next to visible text or inside an already-labeled control. Set `title`, `desc`, or your own `aria-label`, `aria-labelledby`, `aria-description`, or `aria-describedby` to render it instead as a labeled, standalone graphic:

<Showcase resultLabel="Result (inspect to compare)" code={`<!-- Decorative: assistive tech skips it, the button's own label is enough -->
<button><Icon name="mdi:close" /> Close</button>

<!-- Labeled: title becomes the icon's accessible name -->

<Icon name="mdi:alert" title="Warning" />`}>
  <button style="display:inline-flex;align-items:center;gap:0.4rem;font:inherit;color:inherit;background:none;border:1px solid currentColor;border-radius:0.3rem;padding:0.25rem 0.6rem;cursor:pointer">
    <Icon name="mdi:close" size={18} /> Close
  </button>
  <Icon name="mdi:alert" size={24} title="Warning" />
</Showcase>

Inspect those two in your browser's dev tools: the first renders `aria-hidden="true"`, the second renders `role="img"` with an `aria-labelledby` pointing at its own `<title>`.

The `{ id, value }` form lets an element outside the icon reuse the generated `<title>` as its own accessible name, instead of duplicating the text:

```astro
<button aria-labelledby="adjustment-title">
  <Icon
    name="adjustment"
    title={{ id: "adjustment-title", value: "Adjustment" }}
  />
</button>
```

## Deduping repeated icons

`<Icon>` always renders a standalone `<svg>` — deduping between repeated uses isn't built in, but it's one `icon()` integration away. See [“Automatic sprite optimization”](/guides/sprite/) for collapsing repeated uses into one `<symbol>` and many `<use>` elements.

## Usage with framework components

The `<Icon />` component, like any other Astro component, cannot be used directly inside [UI framework components](https://docs.astro.build/en/guides/framework-components/). See [“Framework Components”](/guides/framework-components/) for the `<slot>` pattern that works instead.
