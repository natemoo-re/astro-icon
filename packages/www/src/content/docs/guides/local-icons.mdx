`localSvg()` reads every `.svg` file in a directory, `src/icons/` by default, and watches it in dev: add, edit, or remove a file, and the collection updates without a server restart.

```ts title="src/content.config.ts"
import { defineIconCollection, localSvg } from "astro-icon/collections";

export const collections = {
  icons: defineIconCollection(localSvg()),
};
```

## Naming

A file's path relative to the directory, without its extension, becomes its icon name. Subdirectories join with `/`, so use sub-folders to organize your files into multiple logical sets:

<FileTree>
- src/icons
  - logo.svg
  - annotation.svg
  - logos
    - deno.svg
    - alpine.svg
</FileTree>

| File | Icon name |
| --- | --- |
| `src/icons/logo.svg` | `<Icon name="logo" />` |
| `src/icons/annotation.svg` | `<Icon name="annotation" />` |
| `src/icons/logos/deno.svg` | `<Icon name="logos/deno" />` |
| `src/icons/logos/alpine.svg` | `<Icon name="logos/alpine" />` |

## A different directory

Pass a different directory as the first argument:

```ts title="src/content.config.ts"
icons: defineIconCollection(localSvg("src/assets/icons")),
```

A relative string like that resolves against your project's root, however `content.config.ts` was invoked — `localSvg` figures that out from the loader itself, so you don't need to compute a path yourself. The one exception is bundling icons *inside* a package for consumers to import — see [“Shipping Icons from a Library”](/guides/shipping-icons-from-a-library/) for why that case takes a `URL` instead.

## Combining several local directories

`localSvg()` only reads one directory, but it's a plain `IconSource` like any other — combine several by passing `defineIconCollection` an array, the same way you'd combine any other sources:

```ts title="src/content.config.ts"
import { defineIconCollection, localSvg } from "astro-icon/collections";

export const collections = {
  icons: defineIconCollection([
    localSvg("src/icons"),
    localSvg("src/vendor-icons"),
  ]),
};
```

**Keep icon names disjoint across composed local directories.** A name resolves to whichever source listed it first; if two directories can genuinely overlap, give the later one an `allowed: [...]` allowlist that excludes the shared names, or merge the directories instead.

## Sync logging

Each sync logs how many icons it loaded and how long it took (e.g. `Loaded 42 icon(s) for the "icons" collection in 18ms`), so you can tell whether a slow build step comes from icon loading or something else.

## Optimizing local icons

Astro Icon doesn't run any optimization on local `.svg` files by default — unlike v1, which ran SVGO automatically. Opt in with the `optimize` option and the `svgo()` helper from `astro-icon/optimize`; see [“SVGO & optimize()”](/guides/optimize/).

:::caution
If you were relying on automatic SVGO optimization from v1, see [“Upgrading to v2”](/guides/upgrade/v2/) to restore it explicitly.
:::

## Transforming icon entries

`optimize` runs first, over the raw SVG string; `transform` runs last, over the already-built `IconEntry` — the same hook every source kind shares (see [“Iconify Icons”](/guides/iconify-icons/#options) for the Iconify-side version). Use it for anything that needs the structured entry rather than raw markup, like prefixing an icon's internal `id`s with its own name so rendering it more than once doesn't duplicate them:

```ts title="src/content.config.ts"
import { defineIconCollection, localSvg } from "astro-icon/collections";

export const collections = {
  icons: defineIconCollection(
    localSvg("src/icons", {
      transform: (entry, { name }) => ({
        ...entry,
        body: entry.body.replaceAll('id="a"', `id="${name}-a"`),
      }),
    }),
  ),
};
```

See the [Sources Reference](/reference/sources/#transformfn) for `TransformFn`'s full signature.

## Colors and `currentColor`

`localSvg()` never rewrites a file's colors for you. If an icon looks like a single-color glyph with no `currentColor` anywhere, a sync-time warning names it. See [Troubleshooting](/guides/troubleshooting/#an-icon-ignores-css-color) for the full explanation and the `svgo()` recipe to fix it.
