You can style your icons with custom CSS.

## Custom CSS styles

Customize the styles applied to every icon by using the `[data-icon]` attribute selector.

```astro mark="Icon" mark="[data-icon]"
<Icon name="twitter" />
<Icon name="mastodon" />
<Icon name="threads" />

<style>
[data-icon] {
    font-size: 2rem;
    color: var(--brand-color);
}
</style>
```

Customize the styles applied to a single icon by using the `[data-icon="name"]` attribute selector.

```astro mark="Icon" mark="logo" mark="[data-icon=\"logo\"]"
<Icon name="logo" />

<style>
[data-icon="logo"] {
    font-size: 2rem;
    color: var(--brand-color);
}
</style>
```

## Attributes redeclared on inner elements

Passing a presentation attribute like `stroke-width`, `stroke-linecap`, or `fill` to `<Icon>` sets it on the rendered `<svg>`, and it cascades to every nested element that doesn't declare its own value for that attribute — this is normal SVG/CSS inheritance and works for most icon sets.

It breaks down for icon sets (Tabler is a common example) that redundantly redeclare the same presentation attributes on inner `<path>`/`<g>` elements, not just the outer `<svg>`. Once an element has its own value for a property, it never falls back to inheriting it from an ancestor, no matter what you pass to `<Icon>`:

```astro "stroke-width={3}"
<!-- The outer <svg> gets stroke-width="3", but nested elements keep their
     own redundant stroke-width from the source icon and ignore it. -->
<Icon name="tabler:rss" stroke-width={3} />
```

If you hit this, the fix belongs in the icon set's `optimize` step, not on every `<Icon>` usage: strip the redundant, duplicated attribute(s) from the inner markup so each is only set once, at the root, and can inherit normally. This applies to any presentation attribute redeclared this way — `stroke`, `stroke-width`, `stroke-linecap`, `stroke-linejoin`, `stroke-dasharray`, `fill`, and so on — for any icon source (`iconify`, `localIcons`, or a custom `IconSource`).

```ts title="src/content.config.ts" "optimize"
import { defineCollection } from "astro:content";
import { iconify } from "astro-icon/loaders";

export const collections = {
  tabler: defineCollection({
    loader: iconify("tabler", {
      optimize: (svg) => svg.replace(/\sstroke-width="2"(?=[\s/>])/g, ""),
    }),
  }),
};
```

## Tailwind CSS

Tailwind CSS support in Astro projects is provided by the [Astro Tailwind integration](https://docs.astro.build/en/guides/integrations-guide/tailwind/).
The `Icon` component automatically passes the `class` prop through to the underlying `svg` element.

```astro mark="class=\"text-xl text-emerald-700\""
<Icon name="logo" class="text-xl text-emerald-700" />
```
